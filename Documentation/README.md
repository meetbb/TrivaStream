# TrivaStream Documentation

This folder holds the architectural decisions behind TrivaStream — a record of
what we decided, why, and what we deliberately chose not to do.

## Contents

- **[decisions/](decisions/)** — Architecture Decision Records (ADRs). Each one
  documents a single, specific decision: what problem it solves, what we
  considered, and what it costs.

## Who this is for

These documents are written to be readable by anyone with a stake in
TrivaStream, technical or not — engineers joining the project, technical
leads reviewing direction, and managers who want to understand *why* the app
is built the way it is without reading code. Each ADR opens with a short,
plain-language summary before the technical detail.
