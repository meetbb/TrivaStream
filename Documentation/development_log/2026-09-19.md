# 2026-09-19

## Changed

- Added `BundledContentRepository`, a second `ContentRepository` conformance
  that reads the catalog from a bundled `catalog.json` (3 entries, using
  SoundHelix's public test MP3s). `TrivaStreamApp` now injects it, and
  `StaticContentRepository` was removed since nothing uses it anymore. No
  view or view model changed.
- Each catalog entry is decoded and validated on its own. A malformed entry,
  empty title, or unparseable URL is skipped and logged with `os.Logger`
  (console only). Duplicates are dropped by `url`, first occurrence wins. A
  missing resource or non-array JSON throws `CatalogError`, which reaches the
  UI through the existing `LibraryViewModel.errorMessage`.
- Fixed a main-actor issue found while reviewing concurrency:
  `fetchCatalog()` is `async` but not actor-isolated, so its synchronous file
  read and decode ran on `LibraryViewModel`'s MainActor. The work now runs
  inside `Task.detached`.
- Added `BundledContentRepositoryTests` (6 tests). The full suite, including
  UI tests, passes on the iPhone 17 simulator.

## Decisions

- A bad entry among good ones is skipped and logged rather than failing the
  whole catalog: availability over strictness.
- Duplicate key is `url` only.
- `os.Logger` is used directly in TrivaStream, console only.
- Catalog schema stays at `title`, `artist`, `url`; no artwork field.
- No new abstraction. This is a new conformance of the existing
  `ContentRepository` seam (ADR-003), so ADR-004's triggers did not apply.
- `parse(_:)` is an internal static so tests can pass it synthetic JSON
  without bundle fixtures.
- Used `Task.detached` rather than making the repository an actor. It holds
  no mutable state, so an actor would add nothing.

## Known limitations

- `PlayerViewModel.select(_:)` sets `currentItem` before awaiting
  `load`/`play`, with no guard against overlapping calls. Rapid taps can leave
  the UI and the player disagreeing. Flagged, not fixed.
- The `player.states` observation `Task` in `PlayerViewModel` is never
  cancelled. Harmless with one long-lived instance (ADR-002), but it would
  leak a loop per instance if view models were ever recreated.
- No tests for `PlayerViewModel`. UI tests are still Xcode boilerplate.
- Playback of the catalog's real URLs was not verified end to end here, and
  the SoundHelix URLs' availability is outside our control.
- The catalog is loaded fully into memory as one array, with no pagination.
